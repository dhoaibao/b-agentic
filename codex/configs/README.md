# Codex configuration ownership

Everything in `codex/` except `hooks/b-codex-hooks.mjs` and this README is
generated by `python3 tooling/generate/registry_sync.py` from `skills/`,
`references/`, and `claude/configs/mcp.*.json`. Edit those sources and
regenerate, never the generated files.

| Source                           | Installed path (default `~/.codex`)    | Owner                                                                                   |
| -------------------------------- | -------------------------------------- | --------------------------------------------------------------------------------------- |
| `skills/b-*/SKILL.md`            | `~/.agents/skills/b-*/SKILL.md`        | Codex user skill scope; invoked as `$b-<name>`                                          |
| `agents/b-*.toml`                | `agents/b-*.toml`                      | Five generated read-only specialist roles with a pinned model and effort from the registry (sandbox and MCP keys are omitted: Codex ignores them) |
| `rules/b-agentic.rules`          | `rules/b-agentic.rules`                | Prefix rules: denied and asked shell commands                                           |
| `configs/kernel.md`              | block in `AGENTS.md`                   | Generated kernel between `<!-- b-agentic:start -->` and `<!-- b-agentic:end -->`        |
| `configs/hooks.template.json`    | entries in `hooks.json`                | Hook entries merged by exact value; `$HOME` is expanded to the real home at install     |
| `configs/config.template.toml`   | tables in `config.toml`                | Nine managed `[mcp_servers.*]` tables with per-tool approval modes; no stored credentials |
| `configs/config.clickup.toml`    | same tables                            | Optional ClickUp server, added only after install opt-in                                |
| `hooks/b-codex-hooks.mjs`        | `b-agentic/hooks/`                     | Hand-written adapter for `PreToolUse`, `PostToolUse`, and `Stop`                        |
| `../claude/hooks/b-verify-gate.mjs` | `b-agentic/hooks/`                  | The verify gate, shared with Claude Code; the path guard and ClickUp guard are not used (the adapter applies the snapshot CLI's path rules itself) |
| `../claude/bin/*.mjs`            | `b-agentic/bin/`                       | `b-candidate-snapshot`, the candidate fingerprint for the review gate                   |
| `references/*`                   | `b-agentic/references/`                | Effective MCP policy, capabilities, and the per-specialist MCP allowlist                |

The installer records everything it owns in `b-agentic/install.json`, backs up
each user file it changes under `b-agentic/backups/`, keeps files and hook
entries you modified, owns each managed `[mcp_servers.<name>]` table by name and parsed value
(so Codex rewriting or reordering `config.toml` never orphans it) and keeps one you changed or
already defined,
refuses a symlinked managed directory or manifest, and never writes under
`~/.pi` or `~/.claude`. It never writes `sandbox_mode` or `approval_policy`; those
stay yours. Hook trust lives in `config.toml` under `[hooks.state]` and is tied to
each hook's hash, so review the hooks with `/hooks` after install and after every
update.

Servers use Codex's stdio and streamable-HTTP table shapes. API keys are
environment references (`env_vars`, `env_http_headers`); export them before
starting Codex. Restart Codex after changing MCP configuration.
